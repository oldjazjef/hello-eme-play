# @hello-eme/play-payload

Payload CMS 3 plugin for [`@hello-eme/play`](../play): adds the global `play` with the game's JSON
configuration and an admin editor generated from the schema (`PLAY_SCHEMA` in `@hello-eme/play-schema`).

## Install

```sh
npm install @hello-eme/play-payload
```

Peer dependencies: `payload`, `@payloadcms/ui`, `react`.

```ts
// payload.config.ts
import { playPlugin } from '@hello-eme/play-payload';

export default buildConfig({
	plugins: [playPlugin({ mediaCollection: 'media' })]
});
```

Then run `payload generate:importmap` once: the editor is a client component registered as
`@hello-eme/play-payload/client#PlayConfigField` (the same convention as other Payload plugins).

Websites read the global like any other: `GET /api/globals/play` gives `{ config }`, which goes
to `createPlay({ config })`.

## Options

| Option            | Default         | What                                               |
| ----------------- | --------------- | -------------------------------------------------- |
| `slug`            | `play`          | Slug of the global                                 |
| `group`           | -               | Admin navigation group                             |
| `access.read`     | everyone        | Who reads (the website needs it, no secrets in it) |
| `access.update`   | logged-in users | Who changes it                                     |
| `mediaCollection` | `media`         | Upload collection the picture picker lists         |
| `disabled`        | `false`         | Hides the global but keeps the database schema     |

## The editor

- **Form**: generated by walking `PLAY_SCHEMA`; a new setting in `schema.ts` shows up without touching
  this plugin. Labels and help come from the schema in the admin language (German or English).
- **Only edits are stored.** A value is written once an editor changes it; every field has a reset
  button that removes it again, so defaults (and future default changes) keep applying.
- **Presets** (`PRESETS`) replace the whole JSON after a confirmation.
- **Pictures**: the `url` of a sprite offers the images of the media collection and a link to upload one.
- **Raw JSON** tab: applies when you leave the field; parse errors are shown and nothing is applied.
- **Problems** (`configProblems`) are listed live as warnings. Saving is blocked only when the value is
  no JSON object: `resolveConfig` fixes the rest when the game loads.
- Keys fields take comma separated `KeyboardEvent.code` values or "Press a key" (Esc cancels).

## How the form is built

`NodeEditor` picks a component from `FIELDS` (`src/fields/registry.ts`) by the node's `type`. Components
get `value` (as stored, `undefined` = default), `onChange` (`undefined` = remove), the dotted `path`,
the `ctx` (language, texts, the resolved config for `ref` lookups) and `Child` to render nested nodes.
Pure helpers (immutable updates, renaming records, moving list items, union defaults) are in
`src/state.ts`.

### Adding a node type

1. Add the node type to `@hello-eme/play-schema` (`dsl.ts`).
2. Write `src/fields/<name>.tsx` exporting a component of `FieldProps<YourNode>`.
3. Add it to `FIELDS` in `src/fields/registry.ts`; the registry's type fails to compile until you do.
4. Add the plugin's own strings (if any) to `src/labels.ts`.

## Development

`npm run check|lint|test -w @hello-eme/play-payload`. The tests cover the pure helpers and render the
complete form for the real schema with `react-dom/server`.
